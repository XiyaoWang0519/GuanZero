# 术语对照表

写于 2026 年 11 月 19 日。仓库里的报告和代码注释常用一些项目内部的叫法，这里用大白话
解释它们。英文写法列在括号里，方便在代码和报告里搜索。

新写文档时，能直接说清楚就不要用这些叫法；实在要用，就在第一次出现时解释一遍。

## 1. 模型和对手

| 叫法 | 意思 |
|---|---|
| MLP 模型 / B11 / M1 | 早期的简单网络。B11 是其中最强的一个。它们现在只当对手用，不参与训练 |
| Transformer / history 模型 | 现在训练的模型。会读本局和前几局的出牌记录（历史），再决定出什么牌 |
| DanLM | 外部的一个强掼蛋 AI，是我们衡量棋力的主要对手 |
| 主线（lineage / main） | 一直在往下训练的那一条模型。其他实验从它分出去，测完不一定并回来 |
| uNNNN（如 u234993） | 第 NNNN 次参数更新后保存的模型。数字越大，训练得越久 |
| m1 … m7（里程碑） | 主线每走约 5 亿个决策留下的一个固定存档 |
| 快照（snapshot） | 训练过程中保存的旧版自己。训练时让新模型和这些旧版本对打 |
| 对手池 / 存档池（population / archive） | 训练时可选的旧快照集合 |
| `nearest_pair` | 存档池满了以后，把打法最像的两个快照合并掉一个，而不是删最旧的 |
| 行为探针（behavior probe） | 一组固定的牌局局面，用来比较两个快照的打法有多像 |
| TV 距离 | 两个模型在同一局面下出牌概率的差别大小，0 表示完全一样 |

## 2. 模型内部结构

| 叫法 | 意思 |
|---|---|
| 公共流 / 公共历史（public stream） | 处理所有人都能看到的信息：出过的牌、轮次等 |
| 私有部分（private） | 处理只有自己知道的信息，主要是自己的手牌 |
| 融合（fusion） | 把公共信息和私有信息合到一起的那一层 |
| 主干（trunk） | 合并之后、给每个出牌选项打分之前的那几层 |
| 候选头（candidate head） | 给当前每个可以出的牌（候选动作）打分的部分 |
| critic / 价值网络 | 估计"从这个局面往下打，大概能赢多少"的网络，只在训练时用 |
| 辅助头（aux heads） | 额外的小预测任务，帮模型学得更好。`next` 预测下家下一手出什么，`belief` 猜别人手里有什么牌，`outcome` 预测这一局的结果 |
| response 头 | 预测对手会怎么回应我们出的牌。来自 T7 实验，现在用 `auxiliary` 模式，只当辅助任务，不直接影响出牌打分 |
| `card_counter` 遮挡 | 训练时故意遮住一部分输入，只留手牌、级牌、剩余牌数和当前这一轮的出牌，逼模型自己从历史里记牌 |
| 遮挡预热（obs mask warmup） | 遮挡比例从 0 慢慢升到满，不一下子全遮 |
| 1024 / 512 宽 | 某一层的神经元个数。越宽，模型越大、越慢 |

## 3. 训练过程

| 叫法 | 意思 |
|---|---|
| PPO | 用的强化学习算法。先自己打一批牌，再用这批牌更新模型 |
| 采样 / 收集（rollout / collect） | "先打一批牌"这一步 |
| 学习（learn） | "用这批牌更新模型"这一步 |
| 一次更新（update） | 打一批牌加更新一次模型，算一步。现在一次约 6.5 万个决策 |
| 决策数（decisions） | 模型一共出过多少次牌，用来衡量训练量 |
| logp / 对数概率 | 模型选某个牌的概率取对数。比较两种算法是否算得一样时，常比这个数 |
| ratio | 新模型和打牌时的旧模型对同一个选择的概率之比，PPO 用它控制每次改多少 |
| 熵（entropy） | 模型出牌有多"随机"。太低说明模型过早固定了打法 |
| rank / DDP | 多进程一起训练，每个进程叫一个 rank。DDP 是 PyTorch 的多进程训练方式 |
| 段 / slice / segment | 集群一个作业最多跑 12 小时，所以长训练被切成一段一段，每段结束后自动交下一段 |
| `STOP` 文件 | 在运行目录里放这个文件，训练会保存后停下，也不再续交下一段 |
| 检查点（checkpoint） | 保存的模型文件（`.pt`） |
| 迁移（migrate） | 把旧结构的检查点转换成新结构能读的格式 |
| 续训（resume）/ 冷启动（init） | 从上次停下的地方继续，或从某个检查点重新开一条线 |

## 4. 提速手段

这些都是让"打一批牌"更快的工程优化。按设计，它们只改计算方式，不改结果。

| 叫法 | 意思 |
|---|---|
| KV 缓存（KV cache） | 历史出牌只算一次就存起来，下一步不再重算 |
| 分页缓存（paged cache / page span） | 把 KV 缓存切成固定大小的页来管理，省显存 |
| Triton 分页注意力 | 用自己写的 GPU 程序直接读分页缓存，更快 |
| decoder K/V 缓存 | 把私有部分的一些中间结果也缓存起来 |
| 紧凑投影（compact snapshot projection） | 快照对手的一部分计算合并成更小的矩阵乘法 |
| 合并快照调用（batch snapshot policies） | 多个快照对手一起算，而不是一个一个算 |
| MPS | 让多个进程共用一张 GPU 时少排队的 NVIDIA 功能 |
| 吞吐（throughput） | 每秒能处理多少个决策 |

## 5. 检查和实验管理

| 叫法 | 意思 |
|---|---|
| 门禁（gate） | 正式训练或采用某项改动前的一组自动检查。数值对不上，或速度、显存不达标，就不放行 |
| 冻结回放（frozen replay） | 用同一个模型、同一个随机种子打同一批牌，分别开和不开某项优化，比较两边算出的概率是否一致 |
| 冷 / 长前缀（cold / long） | 冷：从新一局开始比较；长前缀：先打很多手，在历史很长时再比较 |
| 基线 / 对照（baseline） | 不开新改动的那一组，用来做比较 |
| 臂（arm） | 对比实验中的一组配置，比如"开 KV 缓存"是一臂 |
| 逐位一致（bitwise） | 两边结果的每一位二进制都相同 |
| Tier 1 / Tier 2 | 改动的验收等级。Tier 1 要求逐位一致；Tier 2 只要求在浮点舍入误差内一致、出牌分布不变 |
| ULP | 浮点数能表示的最小间隔。差 1 个 ULP 就是"舍入不同"，不算真实差别 |
| parity 测试 | 检查两种实现（如 CPU 和 GPU、开和不开缓存）算出的结果是否一致 |
| 冒烟测试（smoke） | 只确认程序能从头跑到尾、不报错，不测效果 |
| 预检（preflight） | 正式开跑前的小规模检查 |
| 指纹（fingerprint） | 对模型输出或文件算出的校验值，用来确认没被意外改动 |
| 源码身份 / SHA-256 | 对源码包或脚本算的校验值，用来确认远端跑的就是本地这份 |
| 回执（receipt） | 提交作业时留的记录：作业号、提交时间、文件校验值 |
| 套件 / kit | 打包上传到集群的一组脚本、源码和配置 |
| 回退（fallback） | 新配置不达标时，自动换一个保守配置再试一次 |

## 6. 评测

| 叫法 | 意思 |
|---|---|
| 复式（duplicate） | 同一副牌打两遍，双方交换座位，抵消发牌运气 |
| 副（deal）/ 腿（leg） | 一副牌叫一副；复式里的每一遍叫一条腿 |
| 级差 / 每局级数（levels per round） | 每局平均多升或少升几级，是主要的棋力指标。正数表示我们赢 |
| 配对比较（paired） | 两个模型打完全相同的牌，逐副比较，误差更小 |
| 置信区间（如 [0.17, 0.46]） | 在 95% 把握下，真实差距落在这个范围内。区间跨过 0 就说明分不出高下 |
| 外部尺子 | 和 DanLM 打 4,000 副 |
| 内部尺子（`lineage_eval`） | 新版主线和上一版主线打 2,000 副 |
| Botzone | 在线 AI 对战平台，我们的模型在上面有排名 |
| 搜索（search） | 打牌时临时推演几步再出牌，不改模型本身 |
| 确定化（determinization） | 搜索时先随机猜出别人的手牌，再在猜出的牌局上推演 |
| 采样器（sampler） | 搜索时"猜别人手牌"用的方法，`uniform` 是均匀随机猜，`belief` 是用模型的猜测 |
| 触发条件（trigger） | 什么局面下才启用搜索 |

## 7. 掼蛋规则用语

| 叫法 | 意思 |
|---|---|
| 进贡 | 第二局起，上一局输的一方把手里最大的牌（不算红桃级牌）交给赢家 |
| 还贡 | 赢家收到进贡后，还给对方一张 2 到 10 之间、不是级牌的牌 |
| 抗贡 | 输方手里合起来有两张大王时，这一局不进贡 |
| 级牌 | 当前打几，几就是级牌，比 A 还大 |

## 8. 研究诊断用语

| 叫法 | 意思 |
|---|---|
| 习惯（habit） | 对手固定的打法倾向。项目希望模型能从历史里看出对手的习惯并利用它 |
| 风格（style） | 人为设置的不同打法倾向，用来造出各种不同的对手 |
| SWAP 测试 | 把前几局的历史换成别的牌局，看模型的决定变不变。不变说明模型没在用历史 |
| Brier 分数 | 预测准确度指标，越小越准 |
| one-hot 饱和 | 注意力机制只盯着一个位置、其他全忽略，通常说明学习出了问题 |
| QK-norm | 一种让注意力不容易"饱和"的归一化手段 |

## 9. 机器和集群

| 叫法 | 意思 |
|---|---|
| Velocity | 滑铁卢大学的 GPU 服务器，4 张 L40S，免费使用 |
| L40S / 4090 / 5090 | 不同型号的 NVIDIA 显卡 |
| Vast | 按小时租 GPU 的平台，现在暂停使用 |
| Slurm | Velocity 上的排队系统。作业先排队，轮到了才分到显卡 |
| 作业号（如 22151） | Slurm 给每个提交的作业编的号 |
| nice / 优先级 | nice 越大，作业越往后排 |
| 依赖（dependency） | 让一个作业等另一个作业成功结束后才开始 |
