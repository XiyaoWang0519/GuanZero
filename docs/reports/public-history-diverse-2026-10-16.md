## 对手如何选，如何避免挑结果

在本机可用、同一随机初始化 self-play Transformer 主谱系中，先固定八个候选：
u675、u2623、u9989、u20264、u35588、u58528、u73780、u86800。逐一严格加载并
记录 checkpoint SHA、acting-weight SHA、配置、lineage 和 update；不使用 MLP、
人工风格倾斜、重训模型或额外监督。各模型保持自己原有的 norm 配置与权重。

独立筛选题库：64 个开局 seed（主 seed 16102691），每个候选每题采样 32 次。
候选在每题面对完全相同的发牌和公开初始状态，并共用对应抽样随机数。只统计
已经实际打出的公开动作大类：单张、炸弹类、其他；不读私牌、候选集或 forced。

枚举八选四，以每对候选的逐题类别分布平均 TV 为距离，先最大化四者的最小两两
距离，再以平均两两距离破平局。选择只依赖这批公开回答的差异，**不看历史预测
成绩**。正式预测检查使用与筛选不同的比赛及 256 道开局题，避免用同一题选对手
又验证对手差异。

选中：**u2623、u20264、u35588、u86800**。筛选集最小两两平均 TV 0.21631，
平均两两 TV 0.27979。它们也有强弱差异，不把本轮效果单独归因于“相同棋力下的
纯风格变化”。最终是否比旧池分散，还需用独立正式题库复核。

数据中的 `47241..47244` **只是分析器兼容用的四个类别槽位标签**，依次对应上面
四个旧 checkpoint，**不是**上轮 u94482..94488 的原生 snapshot 身份。每个槽位
的实际路径、update 和双重 SHA 都保存在 `selected.json` 与各 wave metadata。
预测时不给真实类别标签；标签仅用于参考计数分组和最后评分。

  不按完成快慢截取。每条件 wave 最多 20,000 vector step；每 worker 1,800 秒。
  四个单线程 CPU worker，无 GPU、训练作业或自动扩样。
- 同样的比赛 seed 16102671，wave 00–07 的 512 场只计参考频率，wave 08–15
  的 512 场独立检验；同 seed 的两次队伍互换及两个己方端点一起分组。
- 历史固定为前三局，从第四局开始预测。两边都看当前局公开局面摘要及当前局
  以前公开的对手行动，仅历史版本增加前三局信息。分析过牌、单张、炸弹类和
  其他四类；不区分强制/主动过牌，不把私牌合法性当作条件。
- 复用**原封不动的上一轮统计代码**：64 伪计数的层次频率表、历史似然除以 8、
  固定随机打乱的错误历史负对照、先按场平均，再按 seed cluster 分层 bootstrap
  10,000 次。主指标仍是 Brier 改善（基线误差减历史误差，正值才是更准）。
- 独立正式同牌题 256 个（seed 16102677），每模型每题 64 次公开回答，前 32
  次作参考、后 32 次检验；合计 65,536 个答案。与之前的题和抽样 seed 相同，
  与新池的筛选题不同。检验历史与牌题交叉配对重采样。
- 上轮追加的直接行为残差规则（固定 32 伪计数）本轮也事先排定复查，不更改
  参数。仍保留原脚本的 exploratory 标记，只作次要诊断，不替代主指标。

真实比赛只能控制公开局面摘要，不能宣称已控制所有未观测私牌；同牌题严格控制
实际发牌和公开初始局面，但只测新比赛第一次领牌的稳定打法，不是第四局或残局
的完整反事实。结论也仅限四个已知候选组成的封闭集合和粗粒度动作预测。

## 结果

### 完整性与独立差异复核

全部 17 个 worker exit code 0，正式采样耗时 **188.08 秒**。完成全部预定
1,024 场、10,351 局、944,584 个公开事件，无超时、按快慢选场或其他排除。
参考组 512 场；独立检验组 512 场 / 128 个 seed cluster，从第四局开始评分
**166,660 次对手公开动作**，其中 24,911 次领牌。与旧池相比动作数不同来自实际
轨迹/比赛长度差异，未强行截断以凑相同动作数，误差先按场平均。

正式独立题库的同题、同抽样随机数比较：四个模型中至少一个回答属于不同动作大类
的比例，旧近邻池 **6.40%**，新池 **54.82%**。配对差 **+48.42 pp**，按题
bootstrap 95% CI **[+44.54, +52.24] pp**。该量不是任意两人出牌不同的概率，
也不是具体卡牌完全相同与否；只比较单张/炸弹类/其他三个大类。

正式题库平均两两 TV 从 **0.02176 → 0.25485**，最小一对的平均 TV 从
**0.01642 → 0.19647**。因此较大的差异在未用于选择的题库中仍存在，不能仅用
“checkpoint 时间隔得远”来替代行为差异证据。

### 主检验：增加前三局是否能预测得更准

以下改善都定义为“共同基线误差减去带历史误差”，正值才表示更准。基线已经使用
当前局公开局面摘要及当前局此前公开的对手动作；检验的只是前三局的额外信息。

| 检验 | Brier 改善 | 配对 95% CI |
|---|---:|---:|
| 真实比赛：基线 − 带前三局 | +0.00010981 | [+0.00008467, +0.00013534] |
| 真实比赛：打乱历史 − 正确历史 | +0.00009532 | [+0.00006115, +0.00012933] |
| 同牌题：同题基线 − 带前三局 | +0.00212414 | [+0.00157719, +0.00272376] |
| 同牌题：打乱历史 − 正确历史 | +0.00239113 | [+0.00168200, +0.00316244] |

真实比赛 Brier 从 **0.46058704 → 0.46047723**，相对误差只降低约 **0.024%**：
增益可靠但非常小，不是出牌正确率提高 0.024 个百分点，更不是胜率提升。
对数误差改善 **+0.00025200**，95% CI **[+0.00019156, +0.00031373]**，方向一致。
同牌题 Brier 从 **0.30097789 → 0.29885375**，相对误差降低约 **0.706%**。

凭前三局推断四个候选中是哪一个，正确率 **41.02%**，配对 seed-cluster 95% CI
**[36.91%, 45.12%]**；随机猜为 25%，旧近邻池为 26.95%。这个辨认指标是描述性
检查，不能取代后续行为的主预测误差。对手身份从未作为检验输入直接给出。

### 与上轮配对比较

按共同的 seed、己方端点和队伍互换配对；两轮使用相同比赛初始种子、参考/检验
划分、固定预测公式、同牌正式题和采样 seed。对四个槽位分层重采样，保留两轮
以及两次队伍互换和两种己方端点的配对。

| 新池相对旧池的变化 | 点估计 | 配对 95% CI |
|---|---:|---:|
| 对手辨认率 | +14.06 pp | [+8.40, +19.73] pp |
| 真实比赛历史 Brier 增益 | +0.00011091 | [+0.00008545, +0.00013648] |
| 同牌题历史 Brier 增益 | +0.00212432 | [+0.00157775, +0.00272467] |

这支持“先前对手过于接近，是先前阴性检验的重要限制”，并在更分散的冻结池中
找到了公开历史的预测信息；不能把全部变化单独归因为纯风格，池中模型的棋力和
诱发的公开局面分布也改变了。真实比赛的摘要控制和同牌开局控制各有上述范围。

### 预定的次要复查：直接照搬前三局偏差仍不可靠

沿用上轮固定 32 伪计数的直接残差公式，不调参、不新增比赛：

| 检验 | Brier 改善 | 配对 95% CI |
|---|---:|---:|
| 真实比赛：基线 − 直接残差 | −0.00092047 | [−0.00133694, −0.00053243] |
| 同牌题：基线 − 直接残差 | −0.00436752 | [−0.00525940, −0.00359435] |

正确历史也没有可靠优于打乱历史（真实比赛差 +0.00021556，CI
[−0.00033551, +0.00075722]；同牌题 −0.00092933，CI [−0.00198898, +0.00003771]）。
因此本轮不是“前三局出什么多，之后照着猜就行”；按候选风格结合当前局面的
频率表有用，不表示任何记忆规则都会有效。

### 用人话说与停止点

**这次确实找到了一点可以反复验证的线索。** 换成差别更大的旧对手后，看前三局
更容易认出对手，也能让后续出牌预测稍微更准；同牌开局对照仍有帮助，排除了这
部分比较中发牌不同的干扰。先前那批近邻快照太像，确实限制了检验。

但真实比赛的预测改善很小，本轮测的是独立公开统计器，不是当前 Transformer
利用历史的能力，也没有测利用这些线索是否能提高胜率。**不能直接宣布模型已经
学会、模型一定没学会、范数 16 有棋力优势，或批准继续训练。** 本轮不自动追加
FULL／ROUND 比赛；下一项实验如需进行，应另行明确范围。

所有模型权重保持冻结，筛选器/分析器未用私牌、候选集或 forced；生产实现、
主线 checkpoint、既有作业未改。正式采样与原检查均为同一本机 CPU / PyTorch
2.14.0 / 已核验 native extension，未使用集群或新训练任务。
