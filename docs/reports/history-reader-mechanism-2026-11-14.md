## 2. 首先排除诊断头失活

这一组严格复用上一轮 reader、固定初始训练集标准化、`128 → 64 → 12` 头、相同初始化及 minibatch，只把 ReLU 换成负侧斜率为 0.1 的 LeakyReLU。分别在原生 Q/K 与 per-head Q/K LayerNorm 下比较。

| reader / 诊断头 | 新测试平衡准确率；95% CI | 选中头的输入梯度为零的训练样本数，三个种子各 /800 |
|---|---:|---:|
| 原结构 + ReLU | 49.86% [48.47, 51.42] | 0 / 0 / 0 |
| 原结构 + LeakyReLU | 50.21% [48.77, 51.79] | 0 / 0 / 0 |
| Q/K 归一化 + ReLU | 52.11% [50.77, 53.43] | 0 / **526** / 0 |
| Q/K 归一化 + LeakyReLU | 51.17% [49.48, 52.76] | 0 / 0 / 0 |

按预定时点采样，每个结构/激活组合有 6 次运行、174 个梯度记录：

- 原结构 ReLU / LeakyReLU 的 Q 梯度非零分别为 **6/174、7/174**。两者诊断头到 reader 输出的梯度都是 174/174 非零；Q/K 饱和不是由头部断梯度造成。
- 归一化 ReLU 的 reader 输入梯度与 Q 梯度非零均为 **121/174**；LeakyReLU 后均为 **174/174**。上轮诊断头失活混淆被实际消除。
- 但修正头之后没有可靠的测试增益：原结构 Leaky−ReLU 为 +0.34 pp，95% CI [−0.07, +0.77]；归一化为 −0.93 pp [−2.35, +0.33]。不能用它支持“ReLU 失活就是全部根因”。也不将无显著差异解释成严格等效。

原结构两种激活的三个种子均选择第 0 步；训练确实跑满预算，只是验证不选后续权重。这里诊断的是新事实头，不是宣称主线动作头失活。

## 3. query 改变了，但完整历史里的读取仍没有明显学会

后续统一使用稳定诊断头：每个样本 12 个读取槽，拼接 12 维问题编号，共享 `140 → 64 LeakyReLU → 1` 头；reader 输出按训练 minibatch 标准化，并在每次候选 checkpoint 用**全部训练集**重新校准均值/方差。验证、测试不参与校准。所有选中模型的 800 个训练样本都有非零头部输入梯度。

六个 attention 版本都复制相同预训练 Q/K/V/out 投影并启用相同 per-head Q/K 归一化。每个版本都是 12 槽，避免把 query 改动混同于输出槽数变化。encoder、原 private-query 网络和原动作头冻结。

| query 与搜索范围 | 新测试平衡准确率；95% CI | 打乱旧历史 |
|---|---:|---:|
| 当前 query，全部前缀 | **51.26% [49.93, 52.62]** | 51.00% |
| 同己方座位的训练集平均 query，全部前缀 | 51.14% [49.97, 52.34] | 51.04% |
| 训练集去均值/按维标准化 query，全部前缀 | 51.97% [50.16, 53.84] | 50.49% |
| 可学习的问题 query，全部前缀 | 51.18% [49.85, 52.57] | 50.51% |
| 当前 query，明确指定上一局/对手座位 | **67.48% [65.62, 69.23]** | 49.47% |
| 可学习的问题 query，明确指定上一局/对手座位 | 58.84% [56.88, 60.79] | 50.80% |

“可学习的问题 query”是 24 个目标绝对座位 × 牌型族向量，从随机初始化学习，增加 3,072 个参数；它获得公开的问题身份，不获得答案。目标范围 mask 仅使用局号、座位和 Play 阶段，**不读取牌型**。

平均、标准化、问题 query 相对“当前 query / 全前缀”的配对增益分别为 −0.12、+0.71、−0.08 pp，区间均跨零。去均值和问题 query 的投影方向确实明显变化，不是干预没有生效；但没有形成可靠的事实读取收益。问题 query 在明确范围下反而比当前 query 低 8.64 pp，本初始化/预算不支持把它当成修复。

保持当前 query，仅加正确公开范围，提升 **+16.22 pp，配对 95% CI [13.66, 18.60]**；九项预定比较的 Bonferroni 调整区间仍为 [12.61, 19.73]。这明确支持本任务存在**定位/筛选困难**。该 mask 是实验给予的地址信息，不是已经被主线自己学会的检索器。

全前缀/当前 query 的 12 槽输入相同；目标 mask 让两个对手得到不同读出。槽数量相同，但 mask 同时提供了问题到历史范围的路由，不能把该增益说成仅仅减少 token 数量的效果。

## 4. 汇聚顺序给出更强的因果对照

这一组固定同样的目标范围、训练集输入标准化、诊断头、初始化、参数量和 12 个最终答案监督。`phi = 128 → 64 LeakyReLU → 128`。没有 token 牌型分类标签，也没有旧分类器迁移。只改变 phi 与汇聚的先后，以及 mean/max 算子：

| 操作顺序 | 新测试平衡准确率；95% CI | 三个种子 | 打乱旧历史 |
|---|---:|---:|---:|
| 先平均 token，再 phi | **64.23% [62.36, 66.05]** | 63.96 / 64.64 / 64.08 | 49.70% |
| 先逐 token phi，再平均 | **82.07% [80.43, 83.70]** | 81.36 / 82.17 / 82.67 | 49.33% |
| 先逐 token phi，再逐特征 max | **94.74% [93.82, 95.61]** | 96.42 / 94.24 / 93.56 | **49.74% [47.68, 51.79]** |

- **只调换非线性处理与平均的顺序：+17.84 pp，95% CI [15.85, 19.85]，调整区间 [14.90, 20.60]。** 先压成均值确实损害了这组可学习的历史信息。
- **再把平均换为 max：+12.67 pp，95% CI [11.13, 14.25]，调整区间 [10.49, 14.92]。** “是否曾经出现过”适合保留单条强证据，平均会稀释稀有事件；这与观察结果一致。
- early-max 的 matched−shuffled 为 **+45.00 pp，95% CI [42.87, 47.12]**。保留当前 query/本局，替换旧局后原答案得分回到随机附近，说明高分依赖历史内容。
- 补充检查：对打乱后的输入，改按其实际 donor 的答案评分，early-max 三个种子仍有 **96.12%、93.45%、92.22%**。置换没有简单把输入破坏成不可解码数据；模型主要是在读取换进去的历史。这个 donor 检查为描述性复核，未用于模型选择或独立区间推断。

三种 pool 方案只在本组内严格比较。它们与 attention 组不同，使用 token 输入标准化和 phi，不能把 attention→early-max 的全部差异单独归于 max。等参数也不等计算量：逐 token phi 比汇总后 phi 做更多计算。

## 5. 实际 attention 在做什么

冻结原模型在新测试 320 个局面、8 个 head 的 2,560 次 top-1 选择中：round 0 有 1,473 次，round 1 有 501 次，题目需要的 round 2 有 586 次。没有选 BOS。原生 attention 的平均熵约为零，接近每头硬选一个 token；对应 query 投影的配对方向余弦为 0.999991。原 reader 平均向量范数约 1,161，跨样本 RMS 变化约 9.08。

单独归一化使平均 attention 熵变为 5.12，但没有自动学会定位：对每道题，正确上一局/目标座位的 attention 质量只有 **7.91%**；均匀读全前缀的对应值为 **8.03%**。稳定诊断头下训练后的 actual-all 也仅约 7.95%。这些是所有测试局面/槽/head 的未加池权重描述均值；不是 attention 对答案的因果贡献分解。

因此，“归一化后梯度有了”与“找到了相关历史”差得很远。原结构有饱和硬选择，归一化后则仍近似混读大部分历史。正确地址能救回一部分，**在压缩之前提取非线性事件证据**能救回更多。最后的 max 又特别符合本轮存在性问题。

这些数值不意味着 early-round token 对真实出牌一定无用，也不能说单个 token 只含该步信息：encoder 是因果上下文化表示。它们描述的是本轮指定历史事实的读取机制。

## 6. 能确认与不能确认

可以确认：冻结 encoder 的信息足以支持可靠的历史事实读取；不需要额外 token 标签；头部断梯度不是修正后失败的解释；单改 query 不足以解决本设置；显式地址与非线性处理/汇聚顺序都有可复现的独立收益。

不能确认：主线究竟因何在 RL 中学成当前参数；模型是否认为历史“没用”；比赛奖励稀疏的贡献比例；这些事实是否包含值得利用的对手风格；max 是否适合所有历史问题；接回出牌后是否提高胜率或净级差。原生 query 的变化对当前事实任务帮助有限，也不能推出它对决策无用。这里 encoder/private 网络冻结、800 场训练、2,000 步预算的负结果不证明其它 query 学习方案不可能成功。

本轮把下一步范围收窄到：在独立副本内，让读取器既能找到相关座位/局段，又在压缩前提取事件证据，再检验这种表征是否改善有决策价值的预测及出牌。**尚未将任何方案接入主线或做棋力声明。**

## 7. 预算、统计与验证

- 13 配置 × 3 种子 × 2 学习率（0.0003、0.001）× 2,000 步，共 **78 次运行、156,000 次独立诊断更新**；batch 32，Adam、无 weight decay，梯度 clip 1。只训练复制的 reader/phi/query 参数与诊断头。
- 本地 CPU，最多 4 worker，每 worker 一个 torch thread。78 次运行耗时合计约 3,146 秒（并发运行时长之和，不是串行墙钟时间）。所有运行实际源码 SHA 一致，且每次验证原 actor state_dict 未改变。
- 5,000 次按类型分层的牌种子组 bootstrap；两方位保持成组。95% 区间描述固定三模型在当前测试分布上的不确定性；不覆盖完整优化随机性或新对手类型。九个预定主要比较另报 `alpha=0.05/9` 的调整区间。
- 打乱历史取同 split、同方位、不同牌种子的 donor，旋转公开座位后与 receiver 原本局后缀拼接并重新编码。历史长度可能变化；这是事实内容负对照，不是纯风格或等长干预。
- 用独立 `public.npz` 原始动作日志复核 **1,280 × 12 = 15,360** 个答案，逐项一致；所有前缀排除未来事件，训练/验证/测试牌种子组互不重叠。
- **24 个相关测试通过**：LeakyReLU 在全部负激活下仍传梯度；显式 mask 不依赖牌型；重复槽与原单 query attention 一致；目标范围之外和 padding 不影响读出；汇聚对照参数相同但保留信息不同；训练校准后梯度有效；按新 replicate 编号正确保持配对 bootstrap；以及既有标签/缓存副本边界检查。
- 原 actor、population 和 owning training source 的 hash 保持不变，`git diff --stat -- train cpp` 为空。已知的旧 CPU cached/reencode 极少数数值差异没有被宣布解决：本轮训练比较统一使用重编码的冻结 memory，原 query 使用 native capture。
