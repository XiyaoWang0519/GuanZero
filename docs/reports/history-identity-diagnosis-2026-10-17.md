# 身份方案为何变差：Q 噪声与对手应对差异诊断（2026-10-17）

用户要求解释[新中后盘试验](history-opponent-sensitive-tasks-2026-10-17.md)中知道身份反而少赢的原因：是 Q 估值不足，还是四个对手根本不需要不同打法。本轮只做冻结模型、本地 CPU 诊断，不启动 PPO，不测试或训练新的历史解码器。

**已完成：负收益的主要直接原因是有限样本 Q 表触发了错误换招。更多估值样本后，新方案在同一批独立配牌上比旧身份方案提高 0.578 个胜率百分点。对手也并非完全无需区别：新方案正确匹配相对同一动作混合有 +0.299 个百分点的收益，但超过更强类型盲先验的总增益仅 +0.165，区间仍跨零。** 本轮的预算、数据复用、主比较、收缩系数、统计方法和停止条件已在正式 rollout 前固定到 `protocol.json`；以下不把先前已看过的确认数据重新称为独立确认。

## 已有证据与要区分的问题

这里的 Q 是“固定候选动作后，模拟打到本局结束的平均胜率”，并非 PPO critic 网络的预测。估值不准首先指有限配牌与后续策略采样带来的 Monte Carlo 误差；本轮没有更新或诊断 PPO critic。

上轮身份方案在 24 个类型条件中换招 8 次，其中 5 次的原估计优势不到 1 个百分点，包含一次估计完全打平仍因 argmax 规则换招。上轮独立确认中，每次换招的配对胜率标准误约 1.2–2.2 个百分点。因此精确知道“对手是哪一个”，不代表有限样本 Q 表已经精确知道“该换哪招”。选择每类最高估计值会挑中正向噪声，身份方案比共享一个动作多出选择噪声机会。

另外，不同对手可以强弱明显不同，却对同一批候选动作保持相同排序；这时知道类型能预测比赛难度，未必能改善动作。相反，即使存在一些真正的类型差异，也可能不足以让更换动作抵消损失。诊断必须分开检查以下三件事：

1. 旧身份方案换招的估计优势在新配牌上是否消失或翻转；更多估值样本后是否减少错误换招。
2. 四类对手的动作相对收益是否确实不同，而非仅有整体强弱差异。
3. 即使差异存在，正确匹配打法能否稳定超过同一动作混合以及较强的类型盲先验。

## 运行前固定的预算

保留上轮全部六个局面和各自候选，不依据上轮负收益更换题目。共 30 个候选，四种冻结对手 u2623、u20264、u35588、u86800；自己的队伍继续使用冻结 control endpoint。任务仍是评分节点对未见手牌均匀重配，从该节点指定对手类型；此前公开前缀由类型中立 control 生成。这是有限候选、单次初始选牌、固定后续策略的受控诊断，不是自然比赛中按历史策略似然加权的私牌后验，也不是完整比赛棋力。

| 数据 | 每类型、每动作配牌数 | 新增评分分支 | 用途 |
|---|---:|---:|---|
| 上轮 A256+B256+确认512 | 1,024 | 0 | 明确复用于拟合、噪声对照 |
| 本轮新估值 A | 1,024 | 122,880 | 与旧 1,024 比稳定性，合并为 2,048 选动作 |
| 本轮独立评价 B | 2,048 | 245,760 | 全部动作封存后才运行 |
| 合计 | 新增 3,072 | **368,640** | 不按结果加样本、不筛局面 |

最多四个本地单 torch 线程 CPU 进程，每块八个世界；引擎无额外线程。18,432 个新世界 seed 与各阶段、各局面、此前所有已运行或已预留 seed 分离。每个世界内保留动作和类型配对。每个评分分支必须打到本局终局，未完成则报错，不使用截断值。

主指标仍为本局我方获胜概率，次指标 `seat_return[0]`。旧数据 1,024 与新 A1,024 合并后选出的身份方案为主方案。其他预定对照包括：原封存的旧512方案、旧1,024单独选、A前64/128/256/512/1,024副单独选，以及 pooled2,048 的收缩方案。

收缩方案将各类型的动作胜率估计向四类平均估计靠拢，系数 λ 固定为 0、0.25、0.5、0.75、1。λ=0 所有类型使用同一个动作，λ=1 完全按类型估计；它检查减少对细小类型差异的信任能否避免错误换招。全部系数和动作均在 B 开始前封存，不依据 B 选择“最好的一档”。不同估值方案可能选出不同先验，报告时明确各自参照。

## 独立估值复验

旧数据合并 1,024 副与新 A1,024 副独立比较：身份首选一致率为 66.67%，各处两两排序一致率平均 88.87%，胜率 Q RMSE 平均 1.78 个百分点，双方首选在对方表中的平均交叉差距为 0.385 个百分点。对照上轮 A256/B256 的 RMSE 3.20、交叉差距 1.03 个百分点，误差和换招分歧的影响均缩小，但精确首选并未全部一致。

合并 2,048 副后，case 1 原先对类型 2/3 使用的动作 4 被撤回，四种类型都选动作 0；case 4 原先对类型 2/3 的动作 2/0 也被撤回，新的估计仅让类型 0 选动作 2。case 2 的均匀先验首选从动作 5 改成 1，因此不同样本量方案的增量不能直接当成同一参照上的学习曲线。动作索引是固定候选表的下标，不是引擎全局 action ID。

合并后的完全身份方案仍在 8/24 个条件中不同于新先验；保留所有六处，未因估值变化再筛局面。上述为独立评价前的估值观察，最终判断仍以 B2,048 的封存政策结果为准。

## 原因拆分与统计范围

对封存身份动作 `a_z`、固定类型盲参考 `a_0`，逐世界计算精确恒等式：

```
身份增益 = 正确匹配收益 + 一般动作变化收益
正确匹配收益 = mean_z Q_z(a_z) − mean_{z,z'} Q_z(a_z')
一般动作变化收益 = mean_{z,z'} Q_z(a_z') − mean_z Q_z(a_0)
```

后两项之和逐样本等于身份增益。若一般动作变化明显为负、匹配收益又不足以弥补，则负数来自换了一批总体较差的动作，不能解释为“身份信息有害”。

主比较为 pooled2,048 身份对自身先验，以及正确匹配对相同动作混合；两项报告固定六处的配对世界 97.5% 区间，均需下界大于零才称本轮主方案确立正收益。其他政策、单处结果和 95% 区间只作诊断，不能挑出最好的一行升级为确认。另报六个局面簇重采样区间；这些局面经过此前初筛，不是新局面的总体样本。

对独立 B 表，另检查去除“类型整体强弱 + 动作总体优劣”后的类型×动作交互；用保留世界内全部协方差的中心化 bootstrap 构造加性无交互零假设，报告交互强度与 plug-in 身份价值相对噪声的诊断。该方法为渐近近似；交互存在不保证最佳动作发生变化，直接在 B 上取每类最大值也有选择偏差，不能把 plug-in 值当成已实现收益。

为避免把“不显著”写成“不需要不同打法”，还计算一个保守上界：对 B 上相对预先封存先验的每个类型、每个其他动作的胜率差，用范围为 2 的配对变量经验 Bernstein 上界，并对六处共 96 个差值联合控制 5% 错误概率；然后逐类型取最大上界、等权平均。理论上的候选内精确身份价值不超过“每类最优 − 这个固定先验”，因此这也是其上界。它只约束相同候选和固定后续策略，不约束其他动作、多步反制或完整比赛。2 个百分点是预设实际意义参照，若保守上界仍超过它，必须保留“尚不能排除有用差异”。

## 独立新配牌给出的原因

全部打法封存后完成每动作新 2,048 副评价；下表固定六处，区间为配对世界 97.5%，单位均为胜率百分点。

| 封存方案 | 总身份增益 | 正确匹配收益 | 一般动作变化收益 |
|---|---|---|---|
| 原512方案 | −0.3316 [−0.5880, −0.0671] | +0.1623 [−0.0224, +0.3387] | −0.4939 [−0.6805, −0.3011] |
| 新 pooled2,048 主方案 | +0.1648 [−0.0773, +0.4008] | +0.2991 [+0.1490, +0.4491] | −0.1343 [−0.3438, +0.0727] |

每行前一列逐样本等于后两列之和。新方案正确匹配已有固定局面上的正向证据，但总收益仍未稳定超过先验，预先指定的两项主比较没有全部通过。不能把匹配收益直接当作身份对最佳类型盲方案的收益，也不能用它宣称任务已达到此前 +2 个百分点验收门槛。

原方案再次独立出现负值，说明上轮 −0.6755 个百分点不只是那一批评价配牌偶然偏低；其负值大小随配牌变化，本轮为 −0.3316。新、旧政策在**同一评价表上**的绝对胜率分别为 68.7744% 与 68.1966%，直接配对提高 +0.5778 个百分点，描述性 95% 区间 [+0.3621, +0.7894]。各自类型盲先验为 68.6096% 与 68.5282%，差 +0.0814 个百分点、区间跨零；不能直接将两行“相对各自先验”的差冒充绝对政策提升。

新主方案总增益的局面重采样 95% 区间为 [−0.0366, +0.5066] 个百分点，匹配收益的局面区间为 [+0.0264, +0.6714]；仍只描述此前筛选的六处。新主方案次指标 PPO 本局回报增量 −0.00216，配对世界 97.5% 区间 [−0.01192, +0.00795]，也没有确立超过先验的收益。获胜概率与 PPO 回报不能互相替代。

### 具体哪些换招排错了

原来八次换招，在本轮新 B 上三次正、五次负。下面列出三个明显的排序翻转；类型编号按 u2623、u20264、u35588、u86800 的顺序从 0 开始，优势均相对原来那一处的固定先验动作。动作编号为候选表下标。

| 局面 / 对手 | 原先换招 | 原512表估计优势 | 新B2,048实际差值 | 新差值标准误 |
|---|---|---:|---:|---:|
| case 1 / u35588 | 0 → 4 | +0.391 pp | −4.688 pp | 1.058 pp |
| case 1 / u86800 | 0 → 4 | +3.711 pp | −2.344 pp | 1.080 pp |
| case 2 / u35588 | 5 → 3 | +0.781 pp | −3.809 pp | 0.905 pp |

这三处错误换招对全六处等权平均的贡献合计 −0.4517 个百分点，其余条件有部分抵消。单次标准误是诊断，不是事后挑选三次比较的多重校正区间；但原方案整体负值和预先封存的新方案整体改善均在独立数据上复现。更多估值后 case 1 的两次换招全部撤回，并在本轮避免了该处 1.758 个百分点的平均损失。

这支持的解释是：**识别身份没有错在“认人”，而是每类动作估值的噪声被 argmax 放大，触发了不值得做的调整。** 当前 Q 不是 critic 网络，本轮没有发现需要修改缓存或回报实现的证据。有限候选和固定 continuation 也限制了能找到的真正反制。

### 对手是否本来就不需要不同打法

不能作这个结论。B 表中去除类型整体差异与动作总体差异后，交互均方为 0.0002093；加性噪声对照均值为 0.00002367，近似 bootstrap p=0.00010，显示动作相对收益确有类型差异。更直接的证据是主方案正确匹配对同一动作混合的 +0.2991 pp，配对区间完全为正。

但差异**小且集中**。下表保留全部六处，B 表“首选”只是独立评价表的点估计，没有重新用它部署或挑选政策。

| 局面 | B表四类型首选 | 新封存方案相对先验（pp） | 新方案匹配收益（pp） |
|---|---|---:|---:|
| 0 | 1 / 3 / 0 / 0 | +1.0132 | +1.1963 |
| 1 | 0 / 0 / 0 / 0 | 0 | 0 |
| 2 | 1 / 1 / 5 / 1 | +0.0732 | +0.4395 |
| 3 | 1 / 1 / 1 / 1 | 0 | 0 |
| 4 | 1 / 1 / 1 / 1 | −0.0977 | +0.1587 |
| 5 | 1 / 1 / 1 / 1 | 0 | 0 |

四处的 B 表点估计为同一首选；其余两处存在不同首选。某些动作与类型的交互即使很明显，也可能只影响较差动作，不改变应选的那一招。例如 case 5 的交互 RMS 为 1.751 个百分点，但四类首选仍相同。因此“能区分对手行为/难度”与“值得换招”必须分开。

直接在 B 表取每类最大值得到的平均 plug-in 身份价值为 +0.3194 pp；加性噪声对照的平均最大值偏差为 +0.0750 pp。前者有选择偏差，后者不是精确校正，两者差不能取代独立政策增益。有限候选理论价值的保守联合 95% 上界为 **3.627 pp**，仍高于预定实际意义参照 2 pp，因而本轮**不能证明身份的潜在最佳价值低于 2 pp，更不能证明它为零**。它只说明已实现的可重复增量很小，尚不足以稳定打败较强的通用动作。

## 结论与运行完成记录

当前负收益的主要直接原因已经定位到**有限模拟估值下的错误换招**。对手存在可利用的细小差异，不能归类为完全无需不同打法；但本轮更精细方案的身份总增益尚未稳定超过更强先验，不能据此把任务升级为 PPO 历史适应的正收益验收题。真正的候选内最优身份价值仍有不确定性，其他候选、多步策略与自然完整比赛也未被覆盖。

全部固定 **368,640** 个新评分分支完成：估值122,880，独立评价245,760，无新增局面或追加预算。调度墙钟分别226.70秒、451.12秒，合计约11.30分钟，不含编写、测试和事后只读复核；不是训练吞吐或棋力测量。没有启动 PPO、GPU、远程作业或历史阶段。

`validation-analysis.json` 已从所有分块重构完整数组，核对18,432个新seed与此前数据及预留世界分离、每个终局胜负与回报、368,640个分支计数、全部封存政策、逐世界分解和全部主汇总。关键源码、五个checkpoint、旧数据及动作封存哈希均一致。`secondary-policy-comparison.json` 仅对原先封存方案补充同一先验和绝对政策的配对比较；没有选新动作或新增rollout。29项相关测试通过。
