# 计划：先验证利用，再用条件习惯检验跨局读取（2026-10-17；10-18 修订）

状态：**设计修订，未实现条件对手、未启动新训练或新测量**。2026-10-18 更正：第 0a、0b 阶段均已完成；原先“降低单轴偏置强度后直接跑 ORACLE / FULL / ROUND”的路线停止。下文替代 10 月 17 日的选强度规则、可选价值复核和三臂启动条件。历史结果保留在各自报告中，不重写为新实验的证据。

本修订把两件事分开：**1a 检查已知习惯能否被 PPO + 当前动作融合利用；1b 设计并筛选稀疏、高影响的条件习惯；两项通过后才做 1c 三臂跨局读取实验。** 不把“触发少”直接当作“值得记忆”。本文件不是租机、暂停主线或增加预算的授权。沿用 9 月 30 日已批准诊断例外的范围：固定只读 Transformer 对手包、从 u2623 续训、ORACLE 可读真实 z；所有权重、数据和结论与主线隔离。

### 当前“理想后验”的信息边界

2026-10-18 源码核查：`bench/habit_identifiability.py` 和跨局脚本通过 `bench/history_value_tasks.py:decision_probabilities` 读取行动座位的实际 observation 和合法候选，再计算两种策略的似然。因此既有后验是**给定实际对手私牌/候选的特权似然诊断**，不是已经实现的纯公开历史贝叶斯后验。0a/0b 的数值作为该仪器的历史结果保留；不能据此宣布公开 ROUND 一定能同样快地识别。

后续必须分开报告：真实 z oracle、特权后验、公开可实现的 FULL/ROUND 后验。公开预测器只能用对应视野的公开事件与当前公开摘要；不能输入对手手牌、合法候选、forced 标记或真实 z。标签只用于离线拟合/评分。可以在独立比赛上拟合并校准公开预测器；在完成该环节前，特权后验筛选仅是诊断，不足以放行 1c。有限候选、有限 rollout 的规划器差值是实测参考值，**不是学习策略收益的严格上限**。

## 1a：强习惯利用检查，只训练 ORACLE 与 ROUND

对手仍为**全程 pass b=4**：u2623 的固定副本，两个对手同一 z，z 每场独立抽一次、整场不变，正负平衡；进贡/还贡保持已声明启发式。不要先跑 FULL，也不在此步改 attention、QK norm 或融合结构。

为只检验“给出答案是否有用”，两臂必须看相同长度的历史：

| 臂 | 历史与标签 | 目的 |
|---|---|---|
| ORACLE（1a） | 本局事件 + 真实 z，仍经现有零初始化 style embedding / 动作融合路径 | 已知类型的利用能力 |
| ROUND | 同一本局视野，无标签 | 可自行从本局公开行动学习的对照 |

**实现缺口：** 当前 `habit_view=oracle` 是整场历史 + z，而 `habit_view=round` 是本局历史且无 z；不能直接把这两个现成开关叫作纯标签对照。1a 开跑前需将历史视野和标签开关解耦，覆盖采集、PPO 重算、缓存、恢复和评估。现有 `style_input` 嵌入保持零初始化；不得靠新融合结构把本检查的答案改掉。若另做旧式 full+z 对 round 的复跑，只能标为同时改变上下文和标签的混杂对照。

### 不把 ORACLE ≈ ROUND 自动判成训练失败

+9pp 是对固定 50/50-blind 规划器的优势。ROUND 能推断强习惯时，两臂相等完全可能是**两者都学会利用**。因此必须同时做冻结 ORACLE 的配对标签干预：同一模型、同一初始发牌/座位/对手真实 z，分别给正确 z 与翻转 z；只改变学习者输入，不能改对手行为。保存同局面的动作分布变化，并对完整配对比赛的真实回报评分。后续轨迹允许因动作不同而分叉，按原始比赛 seed 簇配对统计。

- **利用通过：** 正确标签相对翻转标签有可复现的正向收益，两个训练种子方向一致，合并配对 95% CI 下界 > 0；同时报告 round win 和 PPO `seat_return`，以及收益是否只因错误标签使策略退化。它证明标签被有用地利用，不证明达到搜索规划器水平。
- **ORACLE > ROUND：** 配合标签干预，支持给出类型改善学习策略；不是跨局读取证据。
- **ORACLE ≈ ROUND，但正确标签优于翻转标签：** 已知习惯可利用；ROUND 可能已从本局读出，不诊断 PPO 失败。
- **无标签收益：** 先核查 z 注入、梯度、采集/重算一致性、训练曲线和独立任务价值。只有对相同信息对照确立可利用空间且区间足够窄后，才把 PPO 信用分配/动作融合列为瓶颈候选；不能仅由两臂的零差异定位根因。宽区间是未决，不是等效。

建议预算仍为每臂 2 个训练种子、每次 4,000 万总采集决策，每 500 万保存一次；另报实际 learner 决策数。两臂共 4 次运行、1.6 亿总决策，**仅为待落实预算的方案**。同种子对配对初始化、优化器状态、对手分配和发牌；记录实际匹配率，不能只因 seed 参数相同就声称轨迹配对。单种子缩减版仅作试点，不作结构结论。不自动延长失败或仍上升的学习曲线。

## 1b：把触发频率与条件影响分开

候选策略定义为：

`pi_z(a | o, H) ∝ pi_base(a | o, H) * exp(z * b * g(H, seat) * f(a))`

- `b=4` 固定条件影响，`g` 控制公开状态触发频率；不再以减小 b 制造记忆需求。
- `g` 只依赖动作前公开信息，与 z、隐藏牌型和将要抽到的动作无关。
- `g=0` 时，对同一完整策略输入，两种 z 的动作分布必须与 base 相同；`g=1` 时才加倾斜，所有合法动作仍可选。
- z 每场抽一次，两个对手共享；不随局、触发或搜索分支重抽。FULL 跨局保留公开证据，ROUND 在编码器/缓存层面重置。对手的触发状态不是学习者标签。

### 首个候选：限次残局响应（不是整个残局一直倾斜）

固定规格，尚未测量：`axis=pass, b=4, live_cards=10, responses_per_seat_per_round=1`。

在每个对手座位的 Play 决策之前，若以下公开条件都满足，则 `g=1`：

1. 至少一个**仍在打牌**的座位公开剩牌数在 1–10；已出完的 0 张不计入最小值。
2. 这是对另一个队伍当前未被压过的非 pass 出牌的响应，不是领出，也不是压自己队友。
3. 该座位本局尚未消耗过一次满足上述条件的响应机会。

执行该公开响应后即消耗机会，**包括 forced pass 或其他唯一合法动作**；不能查看私有合法候选后决定是否消耗。每局每个对手最多一次、对手队合计最多两次激活；换局重置计数但不重置 z。只有 pass 与非 pass 同时有正概率时倾斜才改变行为；这类“有效触发”仅在特权诊断日志中统计，不泄漏到公开预测器。公开触发次数与有效信息事件数分别报告。

这个上限避免“有人 ≤10 张”一旦成立就连续几十步暴露风格。强度仍为 4，但机会少也可能让总利用价值归零，**不预设它能通过门槛**。搜索必须允许在对手暴露前的我方准备动作开始；不能等观察到触发动作、后验已经更新后才测信息价值。

炸弹/同花顺（tube）响应是后备候选：触发条件只能用桌面已公开牌型，不能用“对手有炸弹/能压”这种私有条件。冻结对手 roster（如 u2623 vs u86800）也是后备方案：每场固定身份，两边相同先验与配对安排。但历史 checkpoint 的差异不是稀疏性的保证；已有[多 checkpoint 公开预测结果](public-history-diverse-2026-10-16.md)只有小幅预测增益，不能替代决策价值。两种后备方案都需另封存具体协议后重新过 0a/0b，不与首候选混跑或看结果后无限扩样。

### 重新过 0a：在利用之前还有多少不确定性

先用 `bench/habit_identifiability.py` 扩展后的条件版本做廉价筛选，再用独立公开预测器验证。首候选的开发筛选建议 64 场、每场最多 6 局，z 平衡；这是筛选不是正式正结果。不得沿用旧输出目录或旧的“前半局最大 b”选择规则。

必须记录动作前的后验和事件顺序，而不只是半局平均：

- 每局公开响应机会、有效触发、forced/无风格差异次数（后两者为特权诊断），以及首次触发位置。
- 第 2 局起，**我方首次处于 1–10 张公开残局条件、且本局尚无对手触发被消耗的决策点**作为预定 pre-trigger 锚点；缺失锚点的比赛另报覆盖率，不能默默排除。
- 锚点处的 FULL/ROUND 真实类型概率、校准误差，以及每次对手触发前后的后验变化；首次暴露后多少个我方关键决策仍有差距。
- 第 1 局 FULL/ROUND 的同输入一致性，历史跨场随机打乱负对照；所有预测使用动作前信息，不读未来动作或该局结果。

沿用 0.75/0.95 只作**新位置上的筛选目标**：在第 2 局起的 pre-trigger 锚点，先逐场平均，再跨场平均，公开 ROUND < 0.75、公开 FULL > 0.95。特权后验另列，不替代公开门槛。锚点覆盖率和无触发概率必须随结果展示；只在极少数选中锚点满足条件不能绕过下项全样本价值门槛。开发筛选通过后冻结习惯、预测器和阈值，用未见比赛确认；没有候选通过就停止，不启动三臂。

### 重新过 0b：信息差必须改变有价值的决策（必做）

用 `bench/habit_crossround_batched.py` 的扩展版本比较相同条件对手下的规划器。前两局积累历史，第 3 局评分；候选 4、世界 64、换招 margin 0.02 可作开发起点，正式预算/精度在运行前封存。主比较是**公开 FULL 后验规划器 − 公开 ROUND 后验规划器**，另列真实 z oracle 和固定 50/50 prior 参考，不能拿 oracle − prior 代替跨局价值。

- 对手真实轨迹、假设两种 z 的 rollout、似然更新必须使用同一个 g 和同一触发计数。搜索 fork 复制计数，假设世界也继承根节点已经消耗的机会；不能在每次搜索开始时复活习惯。
- 从第 3 局第一个我方公开残局决策开始搜索，包含触发前准备动作；对所有预定比赛评分，包括无触发、无锚点和两规划器相同的零差值比赛。不用搜索分歧、后验差或结果筛选分母。
- 正式确认禁用旧 `SKIP_GAP=0.05` 近似（设为 0）：接近的后验仍可能跨过最优动作边界，不能把被跳过位置当作无价值。候选/Q 精度敏感性在开发集完成，不看确认结果再调。
- 同发牌、z、座位交换、rollout 世界和现场随机数配对；同选时共享轨迹，分歧后独立更新各自后验。按原始比赛 seed 簇 bootstrap，不能把一个比赛里的决策或换座腿当作独立样本。
- **预定实用门槛（提案，不是已测事实）：** 独立确认集上 FULL − ROUND 的第 3 局团队胜率点估计至少 +2pp，配对 95% CI 下界 > 0；同时报告 PPO `seat_return`、按 z 分层、触发覆盖率和搜索分歧率。未达门槛或区间仍宽都不放行 1c。精确确认样本数、种子、资源上限须在运行前定稿，不以“几分钟冒烟通过”代替统计确认。

有限搜索的负结果只说明此任务/规划器未建立足够信号；正结果也不保证 PPO 能学会。因此 1a 和 1b 都不能省略。

## 1c：只有利用检查与条件任务门槛通过后，才运行三臂

| 臂 | 看到什么 |
|---|---|
| ORACLE（1c） | 整场公开历史 + 真实 z；零初始化标签嵌入 |
| FULL | 整场公开历史，无标签 |
| ROUND | 只看本局事件，无标签；编码器与缓存不保留前局 |

此时三臂用 **1b 封存且通过独立确认的条件对手**，不是全程 pass b=4，也不是已失败的 pass b=1 / bomb b=2。全部从相同 u2623 及 Adam 状态开始，网络/PPO/回报/进贡启发式相同，对手分布匹配。1a 的已训练权重不能只给某一臂当起点；1a 的利用结论也不能自动推广到新的条件任务。

原提案的每臂 2 种子 × 4,000 万总决策、每 500 万保存、每个最终 checkpoint 720 个配对种子簇，保留为**待功效与资源复核的候选预算**，不是稀疏任务已有 90% 功效的保证。开发、确认、训练和最终评估种子互不重叠。最终评估完整比赛，主比较 FULL − ROUND，报告比赛胜率、levels/round 和 PPO `seat_return`；ORACLE − FULL 为同上下文标签利用缺口，ORACLE − ROUND 同时改变上下文与标签，不能独自归因。多个正式比较需预先定多重比较规则。

机制诊断：ORACLE 正确/翻转 z 的同模型干预；FULL 的往局历史 SWAP（当前局不变，匹配公开边界并标记分布外限制）；独立数据上的 z 读出；SWAP 与 z 翻转的动作变化方向。第 1 局没有跨局内容，在同一权重/状态下两视野应一致；独立训练的 FULL/ROUND 第 1 局表现仍可不同，不强行要求相等。

| 结果 | 允许的解释 |
|---|---|
| ORACLE 标签干预无收益 | 条件任务上的利用尚未建立；查任务价值、注入/梯度及优化，不归咎历史读取 |
| ORACLE 有标签收益，FULL > ROUND，SWAP 也影响收益 | 本任务中存在跨局内容利用；不是所有 attention 都健康的证明 |
| ORACLE 有标签收益，FULL ≈ ROUND | 才检查读取/融合；读出失败不证明无信息，线性探针成功也不证明信息被动作头使用 |
| 两种子方向不一致或区间宽 | 未决；不自动加时、扩样或加结构臂 |

QK norm、history4 或融合改造属于后续单独因果实验，不能仅凭一次补上缺口就宣布唯一根因，更不能并入主线。

## 实现与执行前清单

以下均为待办，**当前脚本不是上述条件协议的现成实现**：

1. `train/history_habit.py`、`train/history_config.py`：增加独立的条件习惯规格和公共触发状态；历史视野与 oracle 标签解耦，默认关闭、不改变旧 checkpoint 的含义。
2. `bench/habit_identifiability.py`：记录 pre-trigger 时序/覆盖率，明确特权与公开后验，独立匹配的训练/确认数据切分。
3. `bench/habit_crossround_value.py`、`bench/habit_crossround_batched.py`、`bench/batched_rollout.py:SearchRequest`：传递条件规格与消耗状态，参考/批量 rollout 等价。现有 `trigger=10` 只控制搜索启动，**不会让对手只在残局倾斜**。
4. 回归测试：g=0 精确还原 base；g=1 与 b=4 倾斜一致；同局不重复触发、forced 也消耗、换局重置且 z 不变；0 张玩家不误触发；fork/恢复保持计数；不泄漏对手私牌；ROUND 编码器/缓存无前局泄漏；零初始化策略一致；采集/PPO 重算一致；scalar/batched reference 逐位一致。测试源码与 checkpoint/配置 SHA 一起封存。
5. 新鲜输出目录封存协议、源码/权重/规则身份、触发定义、预测器、样本数/种子、采样器、统计口径和硬预算；拒绝混读历史单轴结果。先小规模正确性/吞吐检查，再按封存预算确认。现有速度记录不是新条件任务“几分钟完成”的保证。

**当前停止点：设计已修订，1a 的匹配上下文开关、1b 的条件对手与公开后验尚未实现；没有新的利用、可识别性或价值结果。** 下一执行项是上述本地实现与测试，然后在明确资源上限内做冻结模型筛选/确认；正式 PPO 训练另按既有授权范围落实算力、种子数和预算，不重复申请已批准的三项诊断例外。
