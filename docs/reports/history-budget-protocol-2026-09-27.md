## 第 2 步：冻结的实验方案

### 共同配方

使用 T7 arm B 的配置（`resolved-config.json`），逐项比对一致：宽 64，2 层，4 头，完整历史，辅助响应损失系数 0.1，2 个 PPO epoch，lr 3e-4，clip 0.2，minibatch 2 局，γ=1，λ=0.95。32 个环境 × 64 步，得到每次更新 2,048 个全座位决策。种群为每 2 次更新存一个快照，保留最近 4 个，概率 0.5。CUDA 负责模型推理和学习，CPU 运行引擎，全程 FP32，关闭 TF32。只改 `seed`、`updates` 和检查点间隔。

### 三组（唯一变量）

| 组 | 与对照的唯一差别 |
|---|---|
| control | 无（熵系数 0.01，epsilon 0） |
| entropy | 熵系数 0.03 |
| epsilon | `rollout_epsilon` 0.02；温度 1，重要性权重上限 1，均为实现默认值 |

测试会检查三组配置除声明的变量外全部相同。

- 训练种子为 2026092721、2026092722、2026092723。同一种子的三组初始化权重相同，并在同一 pod 上并发运行，硬件条件也配对。epsilon 组会额外消耗随机数，第一批学习席位之后，轨迹就与对照组不再逐位相同。
- 训练预算按更新数固定，不按墙钟时间：每次运行正好 2,048 次更新，即 4,194,304 个全座位决策，约为 T7 的 2 倍。每次更新都检查决策数必须正好是 2,048，不符即失败。学习行数和优化步数照常记录，另行报告。
- 终点为第 2,048 次更新的 `final.pt`，不按评分挑选。每 128 次更新存一次只含权重的快照，每 32 次更新存一次可恢复的 `latest.pt`。如果期限先到，运行记为未完成，不产生 `final.pt`，之后可以从 `latest.pt` 续跑。

### 续训（第四项）

- 三条 T7 B 谱系各自从 `train/latest.pt` 在新 main 上再训 1,024 次更新（使用 `allow_source_change`），配方不变，共用一个 pod 并发运行。续训终点分别在第 2,000、2,025、1,967 次更新，约 410 万决策，与筛查终点的累计预算接近。
- 比较方式：在同一批牌局上，比较续训终点与各自的 T7 终点，按谱系分别报告并合并。这只描述这三条谱系的训练斜率，不能区分种子波动与环境变化。

### 评估

- 主要评估复用 T7 的开发集（`development.json`，SHA `d7cbd9e0…`）：256 副复式牌（512 轮）和 64 对完整比赛，贪心动作，关闭探索。对手为冻结的 B11 main 和 segment-2 终点，两者哈希都已核对。基线路径已改到 `~/Developer/Projects`。
- 主要指标：对 B11 main 的每轮净级数。次要指标：完整比赛胜率，以及对 segment-2 的两项指标。
- 两个主要比较：entropy − control、epsilon − control。按种子和牌局配对做 bootstrap，报告 95% 区间和 Bonferroni 97.5% 区间。只有 97.5% 区间不含 0 时，才判定某组更好；点估计低于 0.3 级/轮时，在三个种子下记为不确定，因为 T7 实测的种子噪声为 0.2–0.35。不自动晋级任何模型。
- 预先声明的诊断：
  - 第 512、1,024、1,536 次更新的快照，用前 64 副牌和 16 对比赛对 B11 main 评估，只作诊断。
  - control 第 1,024 次更新的快照在完整开发集上评估，与 T7 B 终点对齐，检查复现情况。
  - 按合法动作数和领出/跟牌分层统计熵（排除只有一个合法动作的决策），并报告 max π > 0.99 的决策比例。这一项在评估前实现，不影响训练。
