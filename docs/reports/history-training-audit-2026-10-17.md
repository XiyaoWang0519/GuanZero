# 历史训练经历、收益信号与故障期 checkpoint 审计（2026-10-17）

状态：**离线检查完成。历史和 PPO 梯度路径都通；对手多样性与跨局探索的直接信用有限。故障期有明确退化和后续恢复，但故障前就已存在弱历史使用，不能把当前问题全部归因于这次故障。** 用户随后明确授权查询并下载 velocity 的故障期文件；已完成三份只读下载和 SHA256 核验。没有训练、参数更新、主线行为变更或远端作业变更。

## 问题与证据边界

本轮沿[融合对照](qknorm-fusion-variants-2026-10-17.md)继续查三件事：历史是否
真的进训练、出牌收益能否教到历史部分、旧问题是否造成历史能力退化。

证据包括 owning source、各 checkpoint 的配置/人口池、两个已完成的 120-update
短 PPO 作业日志、一个真实隔离完整 PPO 的 328-row minibatch、11 个旧/新权重
在相同 256 个局面上的冻结对照，以及服务器已有 rank0 标量的只读提取。

它不是所有数十亿训练决策的完整录像，也不是新的训练对照或比赛强度实验。
`protocol.json` 是随取证进展记录的探索性审计范围，不是预注册因果实验。

## 1. 历史是否完整进入训练

### 源码与配置

核对主线与匹配的 qknorm 分支：

- `train/history_rollout.py` 的 MatchEventStore 按 `(env,match)` 保留整场公开
  token；新一局不会清掉该场的旧历史。只有旧比赛不再被引用才被 prune。
- 采集行保存自己的 prefix。`training_batch` 重新从 raw stream 建 batch，
  按每个 match 的最大被引用 prefix 截掉**未来后缀**，不是截掉过去各局。
- `HistoryTrainer.minibatch_loss` 重新编码这些 raw tokens，并非拿 rollout 的
  detached KV 当可训练历史表示；学习路径可以反向穿过 encoder。
- 11 个 checkpoint 的 `window=0`、`habit_view=full`，没有发现本局限定模式。
  max_rounds=16 是局号 embedding 的上限，不等于只保留 16 局的 token；本轮
  固定对照只取第 4 局，不检验更晚局号别名的后果。
- resume 重新开环境、丢弃未完成轨迹和 assignments；这不是在已经进行的
  同一局面里偷偷移除旧前缀，而是新的 rollout session。没有把不同 session
  当作一条连续比赛来核对。

### 已保存的真实训练样本和运行日志

真实隔离 PPO fixture SHA：
`9c3d1018ac52453852536ff5ef497eb1dbcbd553f02e199b30c9570e6c152cd8`。
328 个决策、8 条比赛 stream，prefix 0–852。**296/328 行可以确认含有之前
各局的 token**，最多 781 个；保守旧 token 占每行可见前缀比例的均值为 80.64%。

fixture 没保存每行当前 round_index，因此用最后已见事件的局号作下界，旧局
判定只取比该下界更早的事件；不读取未来事件推断标签。这个计数低估而不会
虚增可以确定的旧历史。

两个短 PPO 作业各 120 条实际日志，学习时 mean prefix 均值为 **524.40 /
542.34**，learn_max_prefix 最高 **2,049 / 1,973**。长度标量本身不能证明
内容正确，但与 raw fixture 和 owning code 一起，不支持“系统性只把本局送进
训练”的解释。四个新测试包括跨局 prefix 保留、未来后缀排除的实际 batch 构造。

## 2. 练习经历是否有利于跨局利用

所有被查 checkpoint 的 snapshot cadence=2、recent=4、snapshot probability=.5，
archive_every=0。新比赛只从最新四个快照抽样；较老 resident 快照可能因正在
进行的比赛而 pinned，不等于这些旧模型仍有资格被新比赛抽到。

最近两个短作业的真实 assignment 日志：

| 条件 | 新比赛 assignments | 四席均为当前 learner | 已知快照在分配时距当前 update |
|---|---:|---:|---:|
| control | 1,334 | 147，11.02% | 0–7，均值 3.49 |
| norm16 | 1,262 | 140，11.09% | 0–7，均值 3.50 |

每个 session/env/match 只分配一次身份；快照在 match 内 pinned 且权重冻结。
身份为 0 的当前 learner 会随着训练更新，不能把它说成整场严格冻结对手。
实际打法多样性还需要行为测量，不能只凭 update 距离断言完全相同；先前
[近快照与多样池公开预测对照](public-history-diverse-2026-10-16.md)已表明当前
近池确实是检出历史价值的一项限制，但这不是全历史训练人口的逐场统计。

奖励是每局 seat_return，写在该队该局最后的行；GAE 在局末设 terminal，
不把下一局 value/reward 接回上一局。**后几局可以通过当下的 PPO loss 学会
读取旧历史；但前几局“先试探，为以后获益”的行动没有得到后几局奖励的直接
信用。** 二者不可混淆：这不是“历史无梯度”，而是跨局探索的训练目标不直接。

这些证据支持“长期不同对手辨认、先试探后利用”的练习机会/直接奖励有限。
不能仅凭配置断言这就是弱历史使用的唯一原因。

## 3. 出牌收益有没有教到历史这一路

只执行 `torch.autograd.grad`，没有 optimizer，没有 step，参数值逐位核对
未变，`.grad` 也未累积。输入是自己的 obs、公开 stream 和记录的优势值等
训练标签；不读 belief 的 hidden 标签，不调用 critic，不把对手私有信息给 actor。

### 原 fixture：正确数学路径上的真实 PPO 目标

原样载入 fixture actor、stored chosen/logp/behaviour_logp/advantage 与 advantage
moments；clip fraction 4.88%。严格使用 owning PPO 的裁剪、优势标准化和行为
权重公式，分开看纯出牌收益目标与已按配置加权的公开 next/outcome/response。

| 项 | encoder 参数梯度范数 | 私有分支范数 | reader 范数 |
|---|---:|---:|---:|
| 纯 PPO 出牌收益 | 0.004615 | 0.545698 | 0.405124 |
| next ×0.1 | 0.246111 | 0 | 0 |
| outcome ×0.1 | 0.007266 | 0.616927 | 0.462822 |
| response ×0.1 | 0.000191 | 0.030588 | 0.023465 |

纯 PPO 确实进入 encoder。选择 7 条可确认有旧局的晚期行，进一步检查梯度位置：
旧局 encoded token 梯度范数 **0.02151**、public projection 梯度范数 **0.000366**；
相应旧局平方梯度占可见部分 76.98% / 83.90%，未来后缀梯度为 **0**。这是
位置上的平方梯度比例，不是跨局奖励占比，也不是历史对胜率贡献的比例。

所以没有发现“出牌收益与历史路径完全断开”。但这批样本中，加权 next 对
**同一组 encoder 参数**的梯度范数约为纯 PPO 的 **53.3 倍**。它支持此处的
学习信号明显偏向公开预测任务；只是一批样本，且省略了 belief 项，不能当成
全程总损失比例或最终 optimizer 更新方向。

原 fixture 的 Q/K 权重坐标梯度约 4.14e−9 / 2.16e−8，V 约 0.0275；配合
旧权重极尖锐的注意力，说明“选择看哪里”的学习也受数值/饱和状态限制。
不同坐标的参数尺度不同，不能单凭小梯度范数宣布绝对不可学习。

**重要边界：** fixture 来自此前保存的隔离完整 PPO 诊断，不是 u74155 主线
首次故障的原始 minibatch。本次是 CPU 正确 math 反向，不是当时错误 efficient
CUDA backward 的复现；实际错误梯度仍以已完成 CUDA 同输入 VJP 为依据。

### 两个当前端点：只检查路径

在同样的真实行和记录优势值上，把 old/behaviour logp 重新锚到各端点当前值，
避免不同权重导致大量 PPO clipping，从而只测梯度是否能传通；这不是实际
on-policy 更新或收益方向验证，不可与原 fixture 定量比较学习进展。

- control / norm16 的 encoder PPO 梯度范数 **0.02031 / 0.03318**；旧局 public
  projection 梯度非零，未来后缀梯度 0；Q/K 也非零。
- 两端点参数均逐位不变，没有累积 `.grad`。这些结果只确认路径仍然通畅。

### 为什么不能把全部弱历史使用归因于故障

m6、m7、u74028 的 encoder 本来就能读出稳定风格线索，但其 reader/state
没有在本固定测试中表现出可靠正增益。由 Q/K 做的 FP64 诊断性重算也显示
旧模型注意力非常尖锐，早于 u74155 的首个已记录大梯度异常；它不是历史
CUDA 内核轨迹的逐位重放。

因此没有证据支持“故障前已经很会利用历史，故障才把这项能力全部打掉”。
更符合证据的是：原本就存在弱使用，故障额外伤到公开预测、编码可读性和
内容敏感度；后续恢复了若干能力，当前端点的后段使用仍不强。

必须保留一个不符合简单单调故事的结果：u77500/77748 的最终 state 对公开
题出现过约 +0.00079/+0.00071 的小正向 FULL−ROUND 增益，而一些更早/更晚
点没有。它不等于更会赢，也不能因为不符合“全都退化”就删掉。故障并不是
所有指标一致下降的单一过程。

当前归一化端点的 reader 比 u86800 更容易读出对手线索，但中间还多了训练
和人口迁移，不能仅凭这条时间线把收益全部归因于某一项修复。最终 state
没有跟着形成稳定的额外收益，与此前融合诊断一致。

## 人话结论

**不是“历史根本没送进去”或“出牌收益完全教不到”。更像是练习条件没有
充分针对跨局利用，原本就有弱使用，数值故障又额外造成了一段明显退化。**

训练对手主要是很近的几个版本；每局奖励也不直接给早期跨局试探记后续功劳。
保存的样本里，出牌收益能传到历史部分，但历史编码器受到的辅助预测信号
很强。这些使“会记牌、会预测，却不太会把历史用于出牌”成为合理解释，
目前还不足以把唯一根因定为训练目标、模型容量或某个融合模块。
